# SyncSpace

SyncSpace is a real-time watch-party demo built with Next.js, React, TypeScript, Tailwind CSS, Express, and Socket.IO. Guests create or join a room with a display name—there are no accounts, authentication, or sign-in flows.

## Quick start

```sh
npm install
cp .env.example .env
npm run dev
```

Visit [http://localhost:3000](http://localhost:3000), create a room, and share its six-character code or invite URL. Guests can join from the link or enter the code and choose a display name.

To run the checks and prepare a production build:

```sh
npm test
npm run lint
npm run build
npm start
```

`npm start` serves the most recent production build. Set `PORT` if the default port `3000` is unavailable.

## Configuration

| Variable | Required | Description |
| --- | --- | --- |
| `PORT` | No | HTTP and Socket.IO port; defaults to `3000`. |
| `HOST` | No | Interface to bind; defaults to `0.0.0.0`. |
| `TMDB_API_KEY` | No | TMDB v3 API key used for popular movie metadata and search. |

With no TMDB key, the discovery page uses the built-in movie catalog. If a configured TMDB request fails, SyncSpace returns the local catalog and displays a fallback notice. Room creation and playback do not need an API key. Keep `.env` private; `.env.example` contains placeholders only.

## What you can do

- Create a room or join by invite code, with no account.
- See room members and connection/reconnection status.
- Synchronize host playback, pause, seek, and supported video changes.
- Transfer host controls to another connected participant.
- Chat, send emoji reactions, suggest videos, and vote on playlist items.
- Join or reconnect to a room and receive its current playback and social state.
- Search/filter movie metadata from TMDB or the local fallback catalog.

Movie listings are discovery metadata, not streams. SyncSpace does not provide commercial movie video or access rights. The host must provide a direct MP4, WebM, or Ogg URL that each participant is authorized to use. Embedded-player pages, arbitrary webpages, HLS, and DRM-protected sources are not supported. Playback can also depend on the source allowing browser access and on the browser's autoplay policy.

## Project structure

```text
app/
  dashboard/page.tsx     Create/join route entry
  discover/page.tsx      Movie-discovery route entry
  room/[roomId]/page.tsx Watch-room route entry
  layout.tsx             Shared navigation and application shell
  globals.css            Shared Tailwind styles and design tokens
features/
  movies/                Movie discovery user interface
  rooms/                 Room creation and watch-room user interfaces
lib/
  browser/guest.ts       Browser-only guest ID and display-name helpers
  movies/
    catalog.json         Local fallback movie metadata
    catalog.ts           Typed catalog exports for the UI
  rooms/types.ts         Shared Socket.IO and room state types
server/
  index.js               Server bootstrap and graceful shutdown
  config.js              Environment parsing and validation
  http/routes.js         Health, movie, and room-creation APIs
  movies/tmdb.js         TMDB integration and local fallback
  realtime/              Socket.IO room event registration
  rooms/room-manager.js  In-memory room state and lifecycle
  validation.js          HTTP and socket payload schemas
tests/
  unit/
    rooms/               Room lifecycle and collaboration tests
    server/              Server configuration tests
```

Next.js route files are intentionally thin; feature UI lives under `features/`, while server-only code is kept separate under `server/`. The server validates room event payloads and applies basic per-socket limits to chat and reactions. Room codes are generated by the server. The guest ID in browser storage is only a reconnect identifier; it is not an account or an authorization boundary.

## Runtime limitations

- Room state is held in memory by a single Node.js process. Restarting the server clears rooms; multiple server instances do not share state.
- Participants have a 60-second reconnect grace period. Empty rooms are then removed. Rooms support up to 20 participants.
- Playback state is broadcast every two seconds, with clients correcting observed drift. Actual latency and drift vary by network, browser, and video source; this repository has no measured performance benchmark.
- This project is intended for local development and demonstration, not production or horizontally scaled deployment.
